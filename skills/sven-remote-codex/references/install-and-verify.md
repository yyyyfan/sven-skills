# 安装和排障经验

以下来自一次真实 Linux x86_64 + Windows OpenSSH + HTTP 代理部署。用于确定检查方向，不将历史版本、模型或主机视为永久默认。

## 完整运行时

先检查 uname -m：x86_64 使用匹配的 x86_64 包，aarch64/arm64 使用匹配的 aarch64 包。从本次官方发布的实际资产列表确认包名和版本，不固定历史版本。远程没有 Node.js 时，可用已有 bash、curl、tar、sha256sum 完成安装，不为安装 Codex 顺带引入 Node.js 或升级系统。

下载中断时保留临时包，针对同一固定版本采用有限次数的断点续传；校验成功后才解压并切换运行时。续传最终失败应报告已完成部分和错误，不无限循环。健康检查超时应考虑下载时的带宽竞争，不能把 GitHub 请求超时直接等同于 SSH 隧道失效。

只下载独立 `codex` 二进制可能缺少 `codex-code-mode-host` 等组件：聊天能响应，但代码工具不能运行。使用官方完整包，保持 bin、资源目录和辅助组件的相对布局。

历史发布布局为 `codex-package-<target>.tar.gz` 和 `codex-package_SHA256SUMS`。使用当前已核实的同一固定版本资源，下载后核对目标文件的 SHA-256；清单中缺项或哈希不匹配时停止安装。不要把下载中或未校验的目录设为当前运行时。

安装到个人版本目录，完成验证后原子切换 current 链接。旧版本保留至新版本验证通过，不在活跃会话期间无提示替换运行时。

Linux 用 `tar --no-same-owner` 解包，保证文件属于安装用户；可执行文件保留正常执行位（通常 0755）。曾出现 root 解包后文件保留打包用户 UID 1001，再 chmod 0700：外部能运行，但沙箱去掉特权后报 Permission denied。应修正新安装文件的归属和权限，不关闭沙箱，也不放宽整个 home 的权限。

## 代理诊断

- 排障先核对实际报错任务的 hostId、SSH 别名和服务器。曾出现用户提供的 IP 正常，而同样的 Connection refused 错误来自另一台服务器的任务；按任务记录对照隧道日志时间，避免修错机器。
- 专用隧道连接不能启用 ClearAllForwardings=yes，否则会清除显式 -R；该选项可用于普通诊断连接以避免重复转发。核对 ssh -G 的生效值和服务器实际监听。
- 新开的 CLI 请求成功后，若桌面端仍报错，继续检查它正在复用的 app-server 环境和日志；条件允许时对同一服务、同一模型作最小请求。控制 socket 已占用可能只表示已有服务在运行，先确认监听与归属，避免盲目删除 socket 或重启所有进程。

- 本地端口能连接，只能证明有监听；实际验证 HTTP CONNECT 和 HTTPS。
- 分别比较本地代理请求、远程经隧道请求、真实模型请求，区分节点问题、转发问题和认证问题。
- 认证网站根路径返回 403 可以证明收到 HTTP 响应，但不能证明登录成功或模型请求可用。
- Windows 自动维护隧道时，使用 `ssh -N -T`，stdin 设为 ignore。不要以“延迟几秒后进程未退出”作为就绪验证；用经转发的实际请求验证。主机校验保持开启。
- 重连按有限退避执行，停止时只终止本启动器的子进程；不使用按名字清理全机 SSH/Codex 的命令。

## 后台维护要求

曾复现两台服务器的本地代理均正常，但远程转发端口连接拒绝，本地已无对应隧道进程。证明的是进程已退出；没有日志时，不能断言具体由休眠、SSH 空闲超时还是聊天会话清理导致。仅设置 ServerAlive 参数不能保证启动器退出后仍然有隧道。

正式交付采用操作系统管理的后台任务，而非工具执行会话中临时保留的进程。Windows 使用当前用户登录自启、单实例任务；进程无需可见控制台，配置异常退出后的有限重启。任务和运行文件放置在稳定路径，避免依赖会话 scratch 目录；明确依赖的 Node/OpenSSH 路径。已有管理任务时先识别目标与所有权，优先更新它，不建立重复的转发。

每个目标独立维护 SSH 子进程并记录状态。建议起点：15 秒保活、3 次未响应退出；约 30 秒从服务器经代理请求 HTTPS，连续两次失败时重建本任务自己的隧道；重连从 5 秒开始退避，持续失败进入数分钟冷却。记录最近成功时间、重试状态和轮转日志，避免日志包含私钥、令牌或完整环境。启动就绪检查必须验证实际转发请求；端口被占用时先查归属，不终止未知进程。

后台进程异常退出或 Windows 任务停止时，需要处理自身子进程的生命周期；不要留下占用端口的孤儿隧道。只按确认归属的 PID 操作，不按 ssh/codex 进程名称批量终止。旧手动启动脚本与新后台方案可能争用端口，应同步更新用户说明并标明唯一推荐入口。

验收：先对每台目标执行能捕获连接拒绝的代理请求；在用户授权的维护范围内主动终止一条确认由管理器创建的隧道，观察同一请求失败、自动恢复及其他目标不受影响。记录实测恢复时间，不把单次结果作为恢复时限保证。登录自启、后台进程重启和整夜休眠恢复分别说明配置状态与实测状态。

电脑关机、休眠、退出 Windows 登录或本地代理关闭期间无法提供这条网络通道。恢复登录和网络后管理器重试，不承诺离线期间可用。HTTPS 健康检查不替代模型认证验证。

## 认证、模型和工具

- `codex login status` 可能显示 Logged in，但缓存的 refresh token 已无效。真实请求出现 invalid_refresh_token/401 时，在个人 CODEX_HOME 下重新登录。
- 设备码会过期，每次现场生成；不要将设备码、认证文件或密钥写入技能。
- 历史默认模型可能已经不支持。查看当前账号模型目录，仅输出模型标识，不输出整个目录中附带的大量提示词元数据。先通过单次 `-m` 验证，再更新个人配置并保留原值；不自动修改共享默认配置。
- WebSocket 重试不一定是代理故障，最终错误可能是型号不支持或认证失败。先读取明确错误，不盲目切换传输或修改内建 provider。某些版本禁止覆盖 `model_providers.openai`。
- 验证依次覆盖：版本/组件完整性、实际新 SSH 会话入口、个人登录、最小模型回复、只读沙箱工具调用。只验证聊天不能宣称远程开发环境完成。
- 使用当前 CLI 的帮助核对诊断命令；历史子命令层级可能变化。

## 保留与撤销

记录本次新增的个人目录、版本、SSH 别名、端口、条件 Shell 片段，以及共享配置的精确差异和备份。撤销仅处理本次管理的项。对已有 shared-root 安装的迁移属于单独任务，不能在保存技能或配置另一台新服务器时顺带迁移。
