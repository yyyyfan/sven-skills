# Sven 的 Codex 远程项目

把 Linux 服务器配置为 Codex 桌面端的 SSH 项目环境。默认使用个人数据和进程环境，兼顾共用 Linux 账号的情况。用中文报告结果。

## 固定偏好与边界

- 远程 `CODEX_HOME="$HOME/.sven/.codex"`。登录、CLI、app-server 均使用该目录；带引号的 `~` 不会展开，使用 `$HOME`。
- 本地 HTTP/mixed 代理默认 `127.0.0.1:7897`。远程回环代理端口首选 `17897`，占用时先确认归属，再选择其他空闲端口，不接管别人的隧道。
- 个人启动入口建议 `$HOME/.sven/bin/codex`；运行时建议 `$HOME/.sven/opt/codex/`。数据目录与程序目录分开管理。
- 用户名、服务器、密钥路径、SSH 端口、跳板机及项目目录按本次目标确定；不要沿用历史服务器、默认 root 或历史密钥。
- 新服务器采用以上默认值。已有服务器只有在用户要求迁移时才迁移，先盘点当前工作流并保留可恢复备份。
- 共用同一个 Linux UID 只能隔开使用习惯，不能防止读取凭据、修改彼此文件或终止进程。需要真正权限隔离时建议独立普通用户；项目使用独立克隆/worktree，资源配额另行配置。

## 执行流程

1. **确认目标与连通性。** 复用用户已提供的连接信息，只追问缺失字段。使用现有可信主机记录和指定密钥进行只读连接，检查架构、Shell、基础工具、本地代理和远程转发权限。不要打印完整 SSH 配置、私钥或认证文件；SSH 配置可能在注释里存放密码，只输出任务所需字段。
2. **确定个人启动方式。** 配置或复用明确的 SSH 别名。对于共用账号，先阅读 [桌面端隔离接入](references/desktop-isolation.md)，确保只有个人连接会找到个人入口。不要把个人 PATH、代理或 CODEX_HOME 无条件写入共用 `.bashrc`、`.profile` 或系统环境，也不要覆盖默认 `~/.codex`。
3. **配置持久代理隧道。** 本地用 OpenSSH 远程端口转发，只请求监听远程回环地址。正式交付使用独立于聊天/终端生命周期的后台管理方式；Windows 默认复用或配置当前用户登录自启任务，单实例运行、隐藏窗口，支持健康检查、退避重连和明确停止。新增服务器优先加入已有管理器，保留其他目标。Windows 使用 `ssh -N -T` 和忽略 stdin；桌面端普通 SSH 连接不重复创建同端口转发。执行前阅读 [后台维护要求](references/install-and-verify.md#后台维护要求)，交付前实测远程 HTTPS 和一次受控断线恢复；进程存活不代表代理可用。
4. **安装完整运行时。** 从当前官方发布获取匹配 Linux 架构的完整 CLI 包及官方 SHA-256 清单，核对后安装。阅读 [安装与故障经验](references/install-and-verify.md)。基础工具不足时明确缺项，按授权范围处理，避免为安装 CLI 顺带升级共享系统。
5. **配置个人入口。** 包装器只为自身及子进程设置个人 CODEX_HOME、代理和运行时路径。个人 config 使用独立文件式凭据存储，使登录确实写入该 CODEX_HOME。保留已有个人配置；按账号实际返回的模型列表选默认模型，不固定历史型号。
6. **登录和验证。** 通过同一包装器运行设备码登录，让用户在本地浏览器完成授权。不要复制共用 `~/.codex` 的令牌。已有登录记录必须以真实模型请求验证有效性；随后在只读沙箱中让模型执行 `uname -s`，确认返回 Linux。测试不修改业务文件。
7. **接入桌面端。** 使用 Settings → Connections → SSH 和实际项目目录。验证桌面端新会话的 CODEX_HOME、启动入口和代理确实属于个人连接。若无法操作桌面端，明确远程端已完成哪些验证、哪些 UI 步骤仍需用户完成，不把 CLI 成功表述为桌面端端到端成功。

## 完成标准

- 个人登录凭据、配置、会话使用 `$HOME/.sven/.codex`，共用默认 Codex 状态未被修改。
- 程序完整、代理实际通畅、模型响应成功、只读工具调用成功。
- 后台任务已独立运行，验证单条受管理隧道中断后的自动恢复，并确认未中断其他目标或桌面端连接。仅配置了登录自启不等于已实测重启/休眠恢复。
- 共用账号情况下：对照普通 SSH 会话，确认其原有 PATH、CODEX_HOME 和默认 Codex 入口未改变；桌面端个人连接单独验证。
- 提供 SSH 别名、项目目录（若已选）、后台任务名、启动/停止方法、状态/轮转日志位置、准确测试结果及撤销方法。当前排障验证采用有限重试；长期后台维护采用有上限的退避及故障冷却，报告持续故障，避免忙循环。
