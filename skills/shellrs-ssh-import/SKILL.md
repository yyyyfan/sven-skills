# 将 SSH 配置导入 ShellRS

把用户指定的本地 SSH 主机配置写入已安装的 ShellRS。用中文报告导入数量、备份位置和实际验证范围。导入请求通常已授权必要的本地写入；沿用用户选择的导入方式。

## 盘点与映射

1. 找到 ShellRS 安装目录、`shellrs-cli.exe`、数据目录及 SSH 配置来源。Windows 常见数据目录为 `%APPDATA%\shellrs`，用户配置为 `~/.ssh/config`；以本机文件为准。tssh 可使用自定义配置路径，核对其配置后再确定来源。历史备份和 `known_hosts` 不是额外主机清单。
2. 只输出必要的主机别名、导入计数、缺失文件等信息。SSH 注释可能包含密码；读取和解析它们时避免把完整配置、私钥、密码或凭据内容打印到工具输出。发布 skill 或脚本时使用虚构示例。
3. 收集具体 `Host` 别名，处理 `Include`、多别名和共享默认值。用本机 OpenSSH 的 `ssh -G <alias>` 获取最终地址、端口、用户和有效选项；它不建立 SSH 连接，但 `Match exec` 可执行本地命令，使用前检查相关配置。通配符和否定模式只参与匹配，不创建字面主机条目。无法解析的分支明确报告，不能宣称已导入全部配置。
4. 映射 `HostName`、`Port`、`User`，将存在的 `IdentityFile` 绝对路径关联为 ShellRS 的 key credential。相同用户和规范化私钥路径复用已有凭据。显式指定的私钥缺失时报告缺项；不要悄悄改成密码登录。多密钥候选需要按目标能力选择并披露差异。
5. 盘点已有主机，用别名及连接端点判断是更新还是新增；重名歧义先解决。更新时保留公共 ID、分组、排序、连接历史、现有备注和关联数据；将来源备注追加或更新为独立导入段，避免重复。

## 选择写入方式

- **官方 CLI：** 接口已启用、应用正在运行时，读取 `hosts/credentials ... --help` 确认本机参数，通过 JSON stdin 写入；密码不放在命令行参数中。CLI 能立即更新应用内存和界面。
- **离线 SQLite：** 用户要求直接写数据库，或 CLI 不可用且离线导入适合当前状态时，读取 [references/sqlite-windows.md](references/sqlite-windows.md)。不把开启外部 CLI 当成离线方式的前置条件。

连接路由、端口转发和身份验证必须以目标版本真实能力为准。将 `ProxyJump` 映射为已保存主机的有序跳板关系；`ProxyCommand` 无法等价表示时报告限制，不用 direct 路由冒充迁移成功。对当前版本没有字段的保活、`IdentitiesOnly`、主机密钥校验、`UserKnownHostsFile` 等选项，仅把非敏感值记入备注，并说明备注不会改变连接行为。Alaya 等工具生成的 localhost 端口仍依赖其隧道。

密码写入系统凭据存储，数据库只保存引用或认证方式。只有确定属于当前任务的密码来源才导入，例如用户维护且语义明确的密码注释；未知注释不当作认证值。已有密码和私钥口令在未要求替换时保留。

## 完成标准

- 所有解析出的具体主机都有新增、更新、保留或未导入的明确结果；重复执行不会新增重复主机或凭据。
- 有一致的导入前数据库备份；离线写入经过事务、外键检查和完整性检查。
- 逐项核验地址、端口、有效用户名、认证方式、私钥引用和跳板顺序；新增密码在凭据管理器中读回比较，仅输出是否一致。
- 应用重新加载后，数据库仍保留导入记录。能读取 UI 或官方 CLI 时核验应用加载结果；不能读取时明确只完成数据库验证。
- 配置验证与连接验证分开报告。导入本身不需要连接每台远程主机；仅在用户要求或验证目标明确需要时进行实际连接。
- 交付主机计数、备份路径、不能等价映射的选项和必要依赖，不暴露凭据。
